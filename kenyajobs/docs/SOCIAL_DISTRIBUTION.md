# Social channel distribution\n\n## Admin configuration\nOpen Admin > Distribution to configure the public WhatsApp and Telegram channel URLs, choose which join buttons appear, enable job categories, and control queue approval.\n\n## Publishing behaviour\n- Scheduled refreshes and the authenticated Scan jobs now action fetch existing job feeds and enqueue eligible jobs.\n- A unique job ID plus channel pair prevents duplicate queue records.\n- Jobs are classified as Kenyan, other African, or worldwide remote. Explicitly expired listings and listings older than 45 days are skipped.\n- New items require approval by default. Approving an item changes it to Ready.\n- WhatsApp Channel posts are admin-assisted: copy the generated post, open the channel, publish it, then mark it as published. The official WhatsApp Channel interface does not expose a supported general-purpose publishing API.\n- Telegram can be published manually. Optional bot publishing uses Telegram Bot API when the bot is an administrator in the target channel.\n\n## Hosting environment\nRequired for scheduled refresh: CRON_SECRET, a long random secret. The cron route fails closed if it is absent. Send it using Authorization: Bearer <secret> or x-cron-key.\n\nOptional for Telegram bot publishing: TELEGRAM_BOT_TOKEN from BotFather and TELEGRAM_CHAT_ID (channel username such as @yourchannel or numeric ID). Keep both values only in hosting secrets, and give the bot permission to post in the channel.\n\nAlso set SITE_URL to the canonical public website URL so announcements use correct job links.\n\n## Scheduler\nConfigure the existing hosting scheduler or an external scheduler to call GET /api/cron/refresh on the desired cadence with the Bearer authorization header. Do not expose the cron secret in a public URL or client-side code.\n
